# Changelog

Release notes for macsmith live in
[GitHub Releases](https://github.com/26zl/macsmith/releases). This file explains
the versioning scheme and points at the canonical notes rather than repeating
them. The layout follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Versioning

Tags are calendar-based, not semantic: `vYYYY.MM.DD-<short-sha>`, for example
`v2026.10.21-70a4c8e`. The date is the day the release was cut and the suffix
is the first seven characters of the released commit, so a tag names exactly
one commit and sorts by date.

Releases are produced by `.github/workflows/release.yml`:

- Automatically: when a push to `main` has passed the Checks, macOS Test and
  Security Scan workflows, the version is generated from the date and the
  commit and the release is published.
- Manually: `gh release create vYYYY.MM.DD-<short-sha> --generate-notes`, the
  Releases page, or running the Release workflow with a version string. Every
  path waits for the same three workflows to succeed on the released commit.

Each release carries `macsmith-<tag>.zip` (a `git archive` of the tagged commit
with a `VERSION` file added), its `.zip.sha256` checksum and a GitHub build
provenance attestation. The notes are generated by GitHub from the pull
requests and commits since the previous tag, after a fixed install and checksum
section. `install.sh` records the `VERSION` file, and `macsmith upgrade` moves
to the newest release after verifying the checksum and the provenance.
